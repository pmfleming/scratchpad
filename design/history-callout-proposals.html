History redesign: Scrubber and History

Built from the code in src/app/ui/dialogs/text_history/, text_history.rs, callout.rs and theme.rs. Today's single callout becomes two separate tools: a Scrubber for the current file and a complete History for any file. The colors are the app's real theme tokens, and both mocks are interactive and share the same sample state.

How it behaves

  • Each row is one change: its summary (operation_summary), then the full path · source.
  • Undone changes sit above a blue Now line at 55% opacity. Applied changes sit below it, newest first.
  • Clicking an applied row undoes through it. Clicking an undone row redoes through it.
  • Saved snapshots show in two ways. A snapshot that undo/redo can reach is a dashed marker. One it can't reach is a plain selectable label under "Snapshots beyond undo".
  • All seven controls are icon-only, and only their tooltips explain them.

Two tools, two buttons

The callout splits into two separate tools. Each has its own button, shortcut and job, and neither opens the other. They show the same document state, because both act on the buffer's real undo history.

1 · Scrubber Current file

A small slider for the file in the active tab. Drag it, or focus it and use the arrow keys. It follows tab switches, and it never shows other files or older snapshots, because those belong to History.

Active tab:

Try it: drag the slider or use the arrow buttons, then switch the active tab. The shaded part of the track is behind a change that can't be replayed.

Behavior

  • The target is always the active buffer (tab_manager.active_tab().active_buffer()). It ignores the temporary buffer selection that navigation::target_buffer keeps today, so the scrubber never acts on a file you aren't looking at.
  • Hollow ticks are undone states, filled ticks are applied states, and diamonds are snapshots that undo can reach (covered_markers). Snapshots beyond undo aren't shown here; the History tool handles them.
  • Dragging previews and releasing applies. While you drag, the footer reads "Undo 3 on release". On release the scrubber makes one apply_text_history_to_entry call, and history_feedback::mark flashes the changed line.
  • A change that can't be replayed is a wall. The track behind it is shaded and the thumb stops there, instead of an error appearing in the status bar afterwards.
  • Keys work only while the scrubber has focus: ←/→ step, and Home/End jump to the original or the latest state. This fixes finding 1, and left/right has no direction mismatch.
  • No file picker and no button to open History, so the two tools stay independent.

2 · History Any file

The complete history. Each row is the state after a change, drawn as a node on one vertical line, and clicking a node goes to that state. Choose Current file, All files, or any other open file from Other file ▾.

History
    Snapshots up to date

    Try it: switch between Current file, All files and Other file. Hover a row to see which changes it affects, click it to move there, or click an older snapshot to browse it. The ⋯ menu holds Clear history.

    Three views

    • Current file follows the active tab and is the default.
    • All files lists every change newest-first, in true order, with a file chip on each row. Each file's current state gets its own now badge, instead of one shared line.
    • Other file ▾ lists every open buffer with its change count, so you can read a file's history without switching tabs. When "switch to the file being changed" is on, clicking a state opens that file's tab.

    Rows

    • Undone states have hollow nodes on a dashed line, still in time order instead of moved to the top.
    • Hovering previews the jump. The rows that would change are tinted, and the hovered row says "Undo 3" or "Redo 2".
    • "Original text" sits at the bottom as the state with nothing applied.
    • Snapshots appear as diamonds on the line. Reachable ones sit beside the matching state, and older ones continue below a dotted line. Browsing one opens a banner with Return to latest (HistoryAction::Return).
    • History has no Undo/Redo buttons, because stepping is the scrubber's job. ↑/↓ still move through a single-file view while the list has focus, in the direction shown on screen.
    • Loading and error text gets a fixed slot in the footer.

    Changes

    • Labeled segmented control for Timeline / By file, and labeled Undo / Redo buttons with standard undo icons.
    • Follow-focus and Clear move into a ⋯ menu. Clear asks for confirmation inline.
    • Group headers show the file name with its folder in muted text, and rows drop the repeated path line. The source shows only through the icon.
    • Diff colors use the first_deleted_text / first_inserted_text that TextHistoryEntryView already has. A replace shows as old → new.
    • Snapshots become pills with a disk icon instead of dashed text. Beyond-undo snapshots use the same pill.
    • Rows where replayable == false get a lock icon and can't be clicked.
    • Arrow keys work only while the callout has keyboard focus, and ↑ moves the Now line up.

    • The single Timeline Now line across files (finding 4) or the click meaning (finding 5).

    Mapping to code

    • Separate entry points: add dialogs.history_scrubber beside dialogs.text_history, plus a ShortcutAction::OpenHistoryScrubber and a StatusBarItemKind::HistoryScrubber. The two dialogs share no open/close state.
    • Scrubber: a new ui/dialogs/history_scrubber.rs that reuses choose_target (from navigation.rs) and covered_markers data for the active buffer only. The arrow-key handling now in handle_text_history_navigation moves here, limited to when the slider has focus.
    • History scope: HistoryTab becomes { CurrentFile, AllFiles, File(BufferId) }. Only the first two are persisted, because buffer ids are per session. Persisted 0 → AllFiles and 1|2 → CurrentFile keep today's settings working.
    • History rows: clicking state k while at n undoes through entry k+1 when k < n, and redoes through entry k when k > n, using the existing apply_text_history_to_entry. The line and nodes would be painted in list.rs, replacing history_pill and render_now_line.
    • Removed from History: the Up/Down buttons in navigation::controls and the crosshair toggle. The toggle moves into the ⋯ menu as a checkbox.
    • Theme: two new tokens, diff_add and diff_del, go in theme.rs.
    • Later, and optional: per-edit times ("2 min ago") would need a timestamp on PieceHistoryEntry and a change to the persisted history format. Neither tool depends on it.
