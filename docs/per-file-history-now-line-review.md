# Per-File History Now Line Review

In the per-file History interface, each expanded file group should behave as a local lens over that file's text changes: applied rows are undo targets, undone rows are redo targets, and clicking any row should move that file to the selected point without disturbing unrelated files. The rows should stay in chronological order within the file group so the user can read the sequence as "oldest to newest" while scanning downward. Undoing a row should mark that row, and any later affected rows in the same file sequence, as undone; redoing should restore undone rows back toward the current state. The visual state should make this clear without extra explanation: normal opacity means applied, muted opacity means undone, and the row tooltip/action should match the actual operation that will happen.

The Now line should represent the current boundary between applied history and redo history for that one file group. It belongs between the newest applied row and the oldest undone row, not at a global workspace position and not repeated for every gap. If every row in the file group is applied, the Now line would sit above nothing redoable and should be hidden. If every row is undone, the Now line would sit at the top of the expanded list and should also be hidden, because showing it there adds noise without helping the user choose a redo target. The useful case is the mixed state: applied rows above/before the boundary remain undoable, undone rows after/below the boundary are redoable, and the single Now line gives the user a stable visual split for that file's local undo/redo timeline.
