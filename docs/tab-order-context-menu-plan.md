# Tab Order Context Menu Plan

Add tab ordering controls to the existing tab right-click menu as a mode selector, not as another way to move individual tabs. Dragging already handles manual positioning, so the context menu should expose higher-level ordering policies: Custom Order, Order by File Name, Order by File Age, and Order by Recent Edit. Custom Order should preserve the current drag-defined order and become the active mode whenever the user manually reorders tabs, while the automatic modes should produce predictable visible order without changing which tab is active.

Place the ordering choices in a new Order Tabs submenu near the existing tab-list placement submenu, separated from file actions and close actions so it reads as a layout preference rather than a file operation. The submenu should show the active mode with the same selected-state treatment used elsewhere in the app, and the labels should be plain: Custom Order, File Name, File Age, and Recent Edit. File Name should sort by display name with stable tie-breaking by path or current order, File Age should use filesystem metadata for saved files while placing untitled tabs consistently, and Recent Edit should use the app's own edit activity timestamp so unsaved edits immediately influence order.

Wire the setting through the tab manager or app state rather than sorting only the rendered tab strip. The implementation should keep the authoritative custom order available, apply automatic ordering consistently to horizontal, vertical, overflow, and background-menu entry points, preserve the active tab across mode changes, and persist the selected ordering mode if other tab layout preferences already persist. Verification should cover switching between all four modes, dragging a tab after an automatic mode has been selected, behavior for settings and untitled tabs, missing file metadata, restart persistence, and parity between the visible tab strip and any tab list or overflow surfaces.
