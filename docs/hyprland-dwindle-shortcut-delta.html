The largest gap is the action map.

Your live Hyprland binds are Super+Arrow → focus, Super+Shift+Arrow → move, and Super+Ctrl+Arrow → resize. Scratchpad's Hyprland profile assigns those Alt equivalents to move, resize, and split. All three directional families differ. [1] [2]

Why “resize up/down” can feel completely wrong: translating your usual Super+Ctrl+↑ / ↓ into Alt+Ctrl+↑ / ↓ currently creates another editor view above/below. It does not resize the existing tiles.

Behavior, not just key names

What “intelligent resize” actually means.

Your live compositor has dwindle:smart_resizing = true. The inspected Hyprland keyboard resize path supplies CORNER_NONE: dwindle searches upward for relevant split ancestors and applies the requested axis delta. Scratchpad already has the core nearest-same-axis ancestor lookup. It is not accurate to describe it as lacking all intelligent resizing. [4] [5]

A simple vertical-resize example

For C, Up moves the B/C divider up: B shrinks, C grows. Down reverses that. If B is active, the same divider motion makes B shrink on Up and grow on Down.

The key names describe signed divider motion—not a promise that the active tile always grows in the arrow's direction. Both inspected algorithms share this sign convention for ordinary keyboard resizing.

Ancestor-aware, not axis-changing

If the immediate parent splits left/right, Up/Down can reach a higher top/bottom split. That may resize a whole subtree, not just the active leaf.

If there is no top/bottom ancestor—for example, only two side-by-side, full-height tiles—Up/Down cannot create vertical space by resizing. A no-op is expected. Reorienting tiles is a move/split operation, not resize.

Scratchpad looks for the nearest matching split axis. Hyprland also suppresses motion along an axis when a target spans both corresponding work-area edges.

Additional deltas

Some dwindle behavior is already there.

  • Moving tiles is more than a swap. Scratchpad removes the active leaf, collapses its old split, finds the closest remaining tile to a directional focal point, and reinserts at 50/50. Its tests cover changing the split axis and nested remove/reinsert. This is genuinely dwindle-inspired. [6]
  • It is not a complete dwindle movement port. The inspected Hyprland implementation explicitly forces insertion to the opposite side when moving toward an immediate leaf sibling. Scratchpad has no corresponding explicit sibling-direction override. Hyprland also has monitor-boundary handling; an editor should instead define its tab-boundary policy. These are source-level differences, not a claim that every ordinary move currently fails.
  • New-tile placement differs. Your live use_active_for_splits=true, smart_split=true and preserve_split=true combine active-target selection with smart insertion orientation and preserved split structure. Scratchpad's Alt+Enter selects the workspace reflow axis and places the new view second; its directional split chords explicitly choose a side. The new view shares the existing buffer, unlike launching an independent terminal.
  • Focus needs a new command family. F6 traversal walks the tree's layout order and wraps. That is useful, but it does not implement geometric left/right/up/down focus without changing layout. Existing ActivateView can perform activation once a spatial neighbor is chosen. [3]
  • Default tests currently preserve the mismatch. tile_management_defaults_share_the_alt_leader asserts Alt+Arrow = move, Alt+Shift+Arrow = resize and Ctrl+Alt+Arrow = split. Those expectations must change with the default contract, not just the documentation. [2]

Why a settings-only workaround is incomplete

Existing move and resize actions can be rebound in [shortcuts], but the new resize chords would collide with the existing directional-split defaults unless those are moved too. The parser accepts Ctrl+Alt+Shift chords. There is currently no focus_tile_left/right/up/down action to bind, and settings cannot replace the resize algorithm or ratio limits.

Migration must be coordinated: move all directional families together, preserve explicit user overrides, detect collisions, and explain the new defaults. Do not keep conflicting old defaults as aliases. Hyprland remains the owner of Super; adding Super bindings to the app does not bypass the compositor.

Prioritized work

Fix the contract before polishing the feel.

  1. P0 · Align focus / move / resize

    Add directional-focus actions; update the Hyprland profile defaults; move explicit splits to the proposed extension chord. Update tooltips, keymap tests and the incorrect documentation table together. Keep other platform profiles unchanged unless explicitly requested.

  2. P1 · Match keyboard resize behavior

    Keep nearest-axis ancestor selection. Pass parent geometry to the resize calculation and convert a configurable logical distance into a ratio delta. Choose and document minimum pane sizes versus dwindle's 5%…95% range; do not blindly drop readability safeguards. Define held-key repeat intentionally.

  3. P1 · Validate nested layouts and movement boundaries

    Add nested Up/Down resize coverage, focus-neighbor tests, immediate-sibling movement cases and no-op behavior at unavailable axes/edges. Ensure one chord invokes one layout action and does not move or edit the caret.

  4. P2 · Extend the workspace analogy

    Add guarded Alt+Q, numbered-tab navigation/transfer and optional tile zoom as separately scoped features. Floating editor windows and compositor/session commands are not prerequisites for the requested parity.

Acceptance checklist

  • Focus: in asymmetric 2-, 3- and 4-tile layouts, Alt+Arrow activates the expected spatial neighbor without tree, ratio or buffer changes.
  • Move: Alt+Shift+Arrow rearranges only the active tile; its view identity, buffer association and caret/selection survive.
  • Resize: Alt+Ctrl+Up/Down changes an existing matching split, never creates a view. Test both child sides and a matching ancestor above a differently oriented parent.
  • No axis available: single pane and two full-height side-by-side panes do not reorient when asked for vertical resize.
  • Scale and clamp: compare several parent extents and UI scales; verify chosen step units, minimum sizes, ratio bounds and saturated no-op reporting.
  • Dispatch: exact modifiers, key release, repeat, focus in editor/search/dialogs, and user override collisions produce only the intended action. Preserve unmodified text navigation.
  • Migration: legacy custom bindings remain deliberate overrides; generated tooltips and manual tables describe the effective bindings, not assumed compositor defaults.
