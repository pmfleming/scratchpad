# Review of show-control-chars implementation plan (final)

Reviewed against `docs/show-control-chars-edge-case-review.md` (the implementation plan that replaced the original write-up) and the current code paths it touches. Three of the open questions from the previous draft have now been verified directly against the source — they are recorded here as concrete findings rather than hedged warnings.

The plan is structurally sound. It maps cleanly onto every issue from the original review: the duplicate `view.show_control_chars` source of truth is collapsed (step 5), the redundant `view.layout_cache.clear()` calls in `status_bar.rs` and `unicode_menu.rs` are removed in favor of the existing `LayoutCacheKey` (step 6), the toggle is gated by live `artifact_summary.has_control_chars()` — which the current code refreshes synchronously through `BufferState::refresh_text_metadata_after_operation` after every edit (`src/app/domain/buffer/state.rs:395-401`, called from `src/app/app_state/workspace/mutation.rs:65`), so the gate is responsive (step 7) — and the implicit `len.div_ceil(2)` cursor split is replaced with named line-ending policies (step 4). The glyph upgrade — Unicode Control Pictures for C0/DEL plus a PUA-mapped Scratchpad symbols font for the bidi/format controls — is a real UX win over the current `<ZWSP>`-style labels and slots into `DisplayTextMap` without architectural change.

**Confirmed: bare CR is a document-side line break, so the current `␍`-only substitution is wrong.** `accumulate_staged_line_count` in `src/app/services/file_service.rs:478-503` increments the line counter on every `\r`, with a `pending_cr` flag that suppresses the second increment when an `\n` follows; the piece-tree's `line_count` and `line_info` queries are built on top of this. That means a CR-only file genuinely has N lines in the document model, and the existing `'\r' => "␍"` arm in `layout.rs:217-218` produces fewer display rows than the document believes exist — confirming the original review's diagnosis. The plan's `␍\n` substitution for bare CR (step 3) is therefore the correct direction; pin it as the chosen contract rather than leaving it as one of two alternatives.

**Confirmed: the proposed PUA range U+E000–U+E01A collides head-on with egui-phosphor.** `egui-phosphor 0.12.0` (the version pinned in `Cargo.toml`) maps every icon into the Private Use Area starting at exactly `U+E000` — `pub const ACORN: &str = "\u{EB9A}"`, with sampled codepoints at `U+E000`, `U+E002`, `U+E004`, … through `U+EE82`, totalling 1,512 entries. The full proposed Scratchpad block (U+E000–U+E01A) sits inside that range. Today the editor's monospace family chain is `[editor_font, CJK fallbacks…]` and does not include Phosphor (`src/app/fonts.rs:98-100, 109`), so an editor-only fallback registration is safe in isolation; but the Proportional family chain *does* include `phosphor` (`fonts.rs:94-105`), and any future surface that renders substituted control glyphs through the Proportional family — status bar, dialogs, context menus — would resolve the same codepoint to a Phosphor icon instead of the intended marker. Move the Scratchpad block into a less-trafficked PUA range (U+F000+ is conventional for editor-private substitutions, and Phosphor's highest sampled codepoint is U+EE82 so U+F000+ is clear) and pin the chosen range in the table.

**Two cursor-mapping decisions are still deferred.** The glyph table proposes `\n` → `␊\n` (len 2), which reproduces the exact `len.div_ceil(2) == 1` collapse called out in the original review — there is no display-space cursor position between the marker glyph and the real newline unless `LineEndingMarker` carves one out explicitly. Pin the contract directly in the table ("marker glyph cell maps to the source `\n`; trailing display newline maps to the cursor immediately after the source `\n`") so step 4 is implementing a stated rule rather than discovering it. The CRLF treatment is the other unresolved fork — step 3 lists "show `␍␊\n` as a two-doc-char combined substitution" *or* "show `␍` for `\r` and `␊\n` for `\n` separately" without choosing, and the test list refers to "CRLF behavior is pinned, including cursor mapping around both source chars" without saying what to. Choose one before writing tests; the simpler local fix is to keep `\r` and `\n` as independent substitutions and let `LineEndingMarker` apply to each, since CRLF is the only multi-doc-char case that would otherwise need a `CombinedCrLf` policy.

**Smaller tightening points.** (a) Step 5's "if backwards session compatibility is needed, OR it into the buffer flag during restore" already exists in `src/app/services/session_store/restore.rs:64-77` — the absorbing migration is in place; the work is "delete the persisting side and the split-time `view.show_control_chars` plumbing in `src/app/domain/tab/layout.rs:258-270`," not designing a new migration. State that explicitly so it doesn't get re-implemented. (b) Step 7 lists "disable the toggle vs. auto-clear the flag" without picking; auto-clear is the less surprising option for a user who toggles on for a clean buffer and then pastes content with controls in. (c) Step 1 registers `ScratchpadControlSymbols-Regular.ttf` for PUA but asserts in prose that "Noto Sans Symbols 2 supports the Unicode Control Pictures block" — and that face is not bundled in `src/app/fonts.rs`. Either bundle a symbols face that covers U+2400–U+241F or fold the C0/DEL glyphs into the same custom font; without it, the C0/DEL row of the glyph table will render as `.notdef` boxes. (d) The test list covers display-side correctness but not round-trip fidelity through clipboard or undo; add tests that copy a selection containing a substituted control and confirm the clipboard string contains the original document bytes (not the displayed glyph), and that paste/undo across substitutions leaves the document untouched. The verification checklist mentions saved-byte fidelity but not clipboard. (e) Sequence-wise: the plumbing fixes (steps 4–8) are independent of the typeface work (steps 1–3) and would deliver every original-review correctness win without waiting on font design, license, and asset pipeline. Ship them first.
