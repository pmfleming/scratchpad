01 / Convert deliberately

Encoding

One file, one encoding choice, two distinct actions. Remove the stack of explanatory cards.

Design reasoning
  • Filename replaces the “Selected file” card. Keep current encoding visible next to the choice.
  • Reopen reads disk; Save writes disk. Never hide that distinction behind “Apply”.
  • Replace the permanent red warning with a contextual warning. Dirty and untitled buffers cannot be reopened.
  • Suggested addition: representability feedback before saving. The sample below is illustrative, not an encoding detector.

02 / Find first

Search & replace

A compact search row with navigation always available. Replacement is a disclosure, not another card.

Design reasoning
  • Keep previous/next beside the match count, even when Replace is collapsed.
  • Use a named scope selector instead of four similar icons. Preserve selection, buffer, workspace-tab and all-tabs scopes.
  • Group results by file; show line number and matching text. Avoid one border around every match.
  • Keep Replace and Replace all labelled. Preserve the app’s replacement eligibility, large-result limits, undo/redo and regex rules.
  • This tiny demo uses browser regex, not the production Rust engine. Replacement buttons explain the proposed action without modifying the sample.

03 / Know where you are

History

A continuous timeline with an unmistakable current boundary. Past and redo states stay in the same list.

Design reasoning
  • Keep Timeline and By file as one segmented control. Flat entries replace repeated pill-shaped cards.
  • One “Now” marker moves with the real undo boundary. Redo rows remain selectable, not disabled.
  • Preserve Follow restored buffer, recovery points and return branches. Don’t make history navigation an implicit disk save.
  • The adjacent text is a proposed current-buffer excerpt, not a promise of diff or detached-preview support.
  • Clear gets an icon and confirmation. Closing the callout does not roll back a history visit.

04 / Quiet until needed
Status
A low-noise status bar and a readable message log. Severity is a cue, not the background of every row.
Design reasoning
  • Keep the bar’s path, location, encoding, history and display controls. Preserve path copying and full-path tooltips.
  • Use text labels for log filters, with counts. Keep severity icons so color is never the only signal.
  • Technical details expand in place; copy is explicit. Historical failures must not be presented as current unresolved errors.
  • Below, the badge means “errors in the log”. Live save failures should additionally show an actionable current warning.
  • On narrow windows collapse secondary readouts into overflow, not the error indicator or encoding action.

One family, four jobs
Shared decisions
Editor font throughout
Keep the chosen font in chrome and content. Titles 22 px; labels 14–15 px; secondary text 12–13 px. Respect UI scaling rather than shrinking long labels.
One surface, not nested cards
Use dividers, alignment and 16–24 px spacing for hierarchy. Controls are 36 px tall with visible focus rings. Accent marks selection; red is reserved for real errors and destructive actions.
Details on demand
Remove permanent instructional paragraphs. Keep filenames, current state, scope and safety-critical warnings visible. Give icon actions accessible names and shortcut tooltips.

  
Implementation boundary & review checklist
  • Visual pass first: shared callout header, field styling, flat lists, labelled controls and responsive wrapping. Keep production command routing and stable widget IDs.
  • Encoding: preserve the saved/dirty/untitled guards. Representability feedback and loss-prevention policy need agreement before changing behavior. Do not silently replace unencodable characters.
  • Search: preserve the distinction between a buffer and a multi-buffer tab, selection anchoring, pending/partial/too-large results, regex errors and disabled replacement states. The browser demo is not a search-engine specification.
  • History: visiting an entry currently changes the actual undo boundary. Retain pending/loading/error states, recovery provenance and return branches. A current-buffer excerpt and clear confirmation are proposed additions, not existing guarantees.
  • Status: domain filters, copy-details and overflow are proposals. Derive real counts from messages; don’t invent timestamps or resolution states absent from the model.
  • Verify: production Mono/Serif/Sans fonts, light/dark, 360 px width, long filenames, keyboard-only use, accessible names and focus retention during async updates. Closing a callout returns focus to its invoker.
